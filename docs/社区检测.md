## 社区检测（Community Detection）功能解析

### 核心概念

**社区检测**是图论中的经典算法，用于**自动发现图中紧密连接的节点群组**。

通俗理解：
- 社交网络中，找出"朋友圈"（互相认识的人聚集在一起）
- 知识图谱中，找出"主题簇"（讨论同一主题的实体聚集在一起）

### 在本项目中的实现

#### 1. 算法：标签传播（Label Propagation Algorithm, LPA）

**算法原理**（代码位于 `LabelPropagation.java`）：

```
初始状态：每个节点都有自己唯一的标签（社区ID）

迭代过程：
  对于每个节点：
    查看邻居节点的标签
    选择出现频率最高的标签
    将自己的标签更新为该标签

收敛条件：
  - 标签变化 < 0.1% 的节点
  - 或达到最大迭代次数（100次）

最终结果：
  具有相同标签的节点属于同一个社区
```

**代码实现**（`CommunityServiceImpl.java` Lines 74-92）：

#### 2. 社区构建流程

**完整流程**（Lines 57-72）：

```
输入：图谱 graphId
  ↓
1. 删除旧社区：removeCommunities(graphId)
  ↓
2. 标签传播检测：detectCommunitiesByLabelPropagation(graphId)
  → 输出：Map<社区ID, Set<节点UUID>>
  ↓
3. 并行构建社区节点（最多10个并发）
  对于每个社区（至少2个成员）：
    a. 获取成员节点的摘要（summary）
    b. 使用LLM合并摘要（BinaryTreeSummarizer）
    c. 使用LLM生成社区名称
    d. 在Neo4j创建 Community 节点
    e. 建立 BELONGS_TO 关系连接成员
  ↓
输出：社区数量、迭代次数
```

**LLM 智能命名**（Lines 126-142）：
```java
// 获取社区内所有节点的摘要
List<String> summaries = getMemberSummaries(graphId, memberUuids);

// LLM 合并摘要（二叉树方式高效处理大量文本）
String mergedSummary = summarizer.summarize(summaries);

// LLM 生成社区名称
String communityName = summarizer.generateCommunityName(mergedSummary);
// 例如："三国时期蜀汉将领群体"、"电子商务支付系统相关实体"
```

### 与其他模块的关系

| 模块 | 关系 |
|------|------|
| **本体管理** | 本体定义"类型"，社区发现"群组"。社区成员可能包含不同类型的实体 |
| **时序图谱** | 社区检测基于当前有效的关系（`invalid_at IS NULL`），时序变化会影响社区结构 |
| **可视化** | 社区可用于图表着色（同一社区的节点用相同颜色） |
| **搜索** | 社区提供结构化浏览，补充关键词搜索 |

```java

```

**2. 并行处理**

- 本项目：使用LLM理解内容，生成有意义的名称（"三国时期蜀汉将领群体"）

**4. 层级结构**（从代码中看到的）

### 优化建议（如果需要改进）

1. **增量更新**：当前是全量重算，对于大图谱（>10万节点）会很慢
2. **算法选择**：目前只用LPA，可以增加Louvain、Leiden等算法选项
3. **社区层级**：当前是扁平的，可以支持社区树（大社区 → 子社区）
4. **时序社区**：可以查看社区随时间的演变（哪些社区合并了、分裂了）
5. **可视化集成**：社区检测结果可以直接用于图表着色

### 总结

社区检测是知识图谱的**自动分类器**：
- **输入**：一个包含N个实体和M个关系的图
- **输出**：K个社区，每个社区是紧密连接的实体群组
- **价值**：从"海量扁平数据"到"结构化知识簇"

它和本体管理、时序图谱一起，构成了知识图谱的三大核心能力：
- **本体** → 定义"是什么"（类型系统）
- **时序** → 记录"何时有效"（时间维度）
- **社区** → 发现"谁和谁相关"（群体结构）
