## 📋 标准模块结构模板

所有已完成的模块都遵循以下标准结构:

```markdown
#### X.X.X 模块名称

**测试目标**: 描述模块功能验证目的

**关键功能点**:
- 功能点1
- 功能点2
- 功能点3 (至少5个)

**预期测试时间**: XX 分钟

##### Skill 配置

**引用的 Skill**:
- `browse` - 页面加载验证
- `qa` - 完整功能测试
- `open-gstack-browser` - 交互式操作测试

**前置条件**:
- ✅ 后端服务运行中
- ✅ 前端服务运行中
- ✅ 用户已登录 (admin)
- ✅ 存在测试图谱
- ✅ 特定前置条件

##### Skill 提示词: 模块名称测试

**页面路径**: `/xxx/xxx`  
**源码文件**: `src/views/xxx/xxx.vue`  
**组件依赖**: `@/components/xxx/xxx.vue`  
**API 文件**: `@/api/xxx.ts` - `functionName()`

```prompt
/browser 或 /open-gstack-browser
[完整测试流程包含6个测试场景]
```

---

##### 开发提示词

> ❌ **缺失模块**。**开发任务**:创建 `src/views/xxx/xxx.vue` + 子组件 + `src/api/xxx.ts`。**核心特性**:(1) 特性1;(2) 特性2;(3) 特性3;(4) 回归测试 X.X.X 全部 X 个场景。

---

##### 关键 API 取证

| 方法 | 路径 | 用途 |
|------|------|------|
| GET | `/api/v1/xxx` | 获取列表 |
| POST | `/api/v1/xxx` | 创建 |
| PUT | `/api/v1/xxx/{id}` | 更新 |
| DELETE | `/api/v1/xxx/{id}` | 删除 |
```
