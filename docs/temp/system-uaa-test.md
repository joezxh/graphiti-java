## 全局测试策略

### 每个测试用例的验证清单

1. **页面加载**：页面是否正常渲染，无白屏、无 JS 错误
2. **数据加载**：表格数据是否成功加载，loading 状态是否正确消失
3. **交互响应**：按钮点击是否有响应，弹窗是否正常弹出
4. **表单验证**：必填字段校验是否生效，错误提示是否显示
5. **数据回填**：编辑时已有数据是否正确回填到表单
6. **操作反馈**：成功/失败是否有 message 提示
7. **状态更新**：操作后列表数据是否自动刷新
8. **权限控制**：`v-has-permi` 指令是否正确控制按钮显隐
9. **控制台检查**：浏览器控制台是否有报错或警告

### 通用测试模式

每个模块遵循 **CRUD 测试循环**：

```
1. 打开页面 → 验证列表加载
2. 搜索/筛选 → 验证条件过滤
3. 点击「新增」→ 验证弹窗/表单初始化 → 填写并提交 → 验证列表刷新
4. 点击「编辑」→ 验证数据回填 → 修改并提交 → 验证更新生效
5. 点击「删除」→ 验证确认弹窗 → 确认删除 → 验证列表更新
6. 边界测试 → 空数据、超长文本、特殊字符、并发操作
```

## 问题发现与自动修复流程

### 三阶段闭环

```
阶段 1：问题发现（Detect）
  → 浏览器测试发现异常
  → 截图记录当前状态
  → 记录控制台错误日志
  → 标记失败测试用例

阶段 2：问题定位（Diagnose）
  → 根据错误信息判断问题层级：
    - 前端渲染问题 → 检查 Vue 组件
    - API 请求失败 → 检查 Network 面板（状态码、响应体）
    - 后端逻辑错误 → 检查后端日志
    - 数据问题 → 检查数据库状态
  → 定位到具体文件和行号

阶段 3：自动修复建议（Fix）
  → 输出修复方案（代码 diff）
  → 常见修复模式：
    - 组件未导入 → 补充 import
    - API 路径错误 → 对齐后端路由
    - v-model 绑定问题 → 检查响应式
    - 权限码不匹配 → 对齐前后端权限标识
    - 表单初始值缺失 → 补充默认值
  → 修复后自动重新执行失败的测试用例
```

### 常见错误自动匹配表

| 浏览器现象 | 可能原因 | 检查文件 |
|-----------|---------|---------|
| 白屏 | 路由组件未注册 / import 路径错误 | `route-helper.ts`, `views/` |
| 表格无数据 | API 返回 code≠0 / 后端未启动 | `request.ts`, Network 面板 |
| 弹窗打不开 | `v-model:open` / `v-model:visible` 绑定问题 | 对应 FormModal.vue |
| 表单不回填 | watch 未监听 / props 延迟 | FormModal.vue 的 watch |
| 按钮不显示 | 权限码不匹配 | `access.ts`, 后端权限配置 |
| 401 错误 | Token 过期 / 刷新 Token 逻辑失败 | `request.ts`, `auth.ts` |
| 删除失败 | 外键约束 / 关联数据未清理 | 后端 Service |
| 分页异常 | pageNo/pageSize 参数不对 | API 请求参数 |
| 树形不展开 | `handleTree` 函数异常 | `menuTreeUtils.ts` |
| 表格列错位 | columns 定义顺序与数据不匹配 | index.vue 的 columns 定义 |
| DictTag 不显示 | 字典类型未注册 / 值为空 | `DictTag.vue`, 后端字典表 |

### 快速修复对照表（按症状）

#### 症状：表格数据加载不出来

```
排查路径：
1. 检查 Network 面板 → 找到失败的 API 请求
2. 确认状态码：401=未认证, 403=无权限, 500=服务端错误
3. 如果是 200，检查 response body 的 code 字段
4. 如果 code≠0，检查 message 字段的错误信息
5. 对照 API 文件中的接口路径，确认前端请求路径是否正确

典型修复：
- 路径写错：修改 src/api/xxx.ts 中的路径
- 后端未实现：检查后端 Controller 是否有对应接口
- 缺少参数：检查 API 调用时是否传了必要参数
```

#### 症状：表单弹窗能打开但不回填数据

```
排查路径：
1. 检查 openForm 函数中是否调用了 get/detail 接口
2. 检查 API 返回的字段名是否与 formData 的 v-model 字段名一致
3. 检查 watch 中是否有深度监听（deep: true）
4. 检查 formData 是否使用了 ref()（非 reactive()）

典型修复：
- watch 缺少 immediate：在 watch 中添加 immediate: true
- 字段名不匹配：修改 formData 的字段名对齐后端返回
- 异步加载未完成：使用 loading 遮罩，等数据返回后再显示
```

#### 症状：新增按钮点击后弹窗内表单有残留数据

```
排查路径：
1. 检查弹窗是否使用了 :destroy-on-close="true"
2. 检查 openForm 函数中 formData.value 是否被完全重置

典型修复：
- 添加 destroy-on-close：在 a-modal 上加 :destroy-on-close="true"
- 手动重置：在 openForm 中添加 formData.value = { status: 0, menuIds: [] }
```

#### 症状：树形复选框父子不联动

```
排查路径：
1. 检查 a-tree 是否设置了 :check-strictly="true"
2. 检查 handleTreeCheck 函数是否实现了父子联动逻辑
3. 检查 findAncestorIds 函数是否能正确找到祖先节点

典型修复：
- 如果需要联动：设置 :check-strictly="false" 或在 handleTreeCheck 中手动实现
- 如果只需要叶子节点：在提交前过滤掉非叶子节点 ID
```

**API 封装**（建议创建 `src/api/uaa/mediator.ts`）：
```typescript
export const mediatorApi = {
  page: (params) => get('/admin-api/uaa/mediator/page', { params }),
  list: (params) => get('/admin-api/uaa/mediator/list', { params }),
  get: (id) => get(`/admin-api/uaa/mediator/get?id=${id}`),
  getMy: () => get('/admin-api/uaa/mediator/my'),
  create: (data) => post('/admin-api/uaa/mediator/create', data),
  update: (data) => put('/admin-api/uaa/mediator/update', data),
  delete: (id) => del(`/admin-api/uaa/mediator/delete?id=${id}`),
  deleteList: (ids) => del(`/admin-api/uaa/mediator/delete-list?ids=${ids.join(',')}`),
  updateStatus: (data) => put('/admin-api/uaa/mediator/update-status', data),
  audit: (data) => put('/admin-api/uaa/mediator/audit', data),
  statistics: (id) => get(`/admin-api/uaa/mediator/statistics?id=${id}`),
};
```

【问题诊断】
- 调解员列表为空 → 检查 mediatorApi.list() 或 mediatorApi.page() 是否成功
- 创建失败 → 检查必填字段（realName 必填，userId 和 orgId 需为有效值）
- 审核接口 403 → 检查权限码是否为 `system:mediator:audit`
- 统计接口 500 → 检查调解员 ID 是否有效，统计逻辑是否正常
- 删除失败（有进行中案件） → 后端应先检查是否有进行中的案件
- 调解员关联机构失败 → 检查 orgId 是否为有效调解机构 ID
- userId 冲突 → 一个用户只能绑定一个调解员记录
```
